# Подключение к настоящему Flask-бэкенду

`app.py` — временный адаптер для проверки фронтенда. Не переносите его in-memory store в production и не подменяйте им уже написанные модули команды.

## 1. Маршруты и endpoint-имена

Шаблоны используют `url_for`. Если архитектор применяет Blueprint, замените, например, `url_for('today')` на `url_for('web.today')` или сохраните совместимые endpoint-имена.

| Метод и путь | Endpoint в демо | Назначение |
|---|---|---|
| GET `/` | `index` | Перенаправление на `/today` |
| GET `/today` | `today` | Дневной план |
| GET `/habits?type=all\|useful\|replacement` | `habits` | Список и фильтр |
| GET `/habits/new` | `new_habit` | Создание |
| GET `/habits/<id>/edit` | `edit_habit` | Редактирование |
| POST `/habits/save` | `save_habit` | Отправка формы привычки |
| POST `/habits/<id>/log` | `log_habit` | Полное выполнение, минимум, отмена |
| GET `/support` | `support` | Поддержка |
| POST `/support/step` | `support_action(action='step')` | Выбор мягкого шага |
| POST `/support/skip` | `support_action(action='skip')` | Пропуск |
| GET `/statistics` | `statistics` | Показатели и календарь |
| GET `/schedule` | `schedule` | Пауза и расписание |
| POST `/schedule/save` | `save_schedule` | Сохранение / пауза / возобновление |
| GET `/settings` | `settings` | Настройки интерфейса |
| GET `/auth?tab=login\|register` | `auth` | Общая карточка входа |
| POST `/login`, `/register` | `demo_auth` | Пока только редирект |
| GET `/logout` | `logout` | Заглушка выхода по ТЗ |
| POST `/demo/reset` | `reset_demo` | Только демо; удалить при интеграции |

После успешного POST стенд возвращает **303 Redirect**. Это паттерн Post/Redirect/Get: обновление страницы не повторяет отправку формы.

## 2. Поля форм

### `POST /habits/save`

Формат: обычный `application/x-www-form-urlencoded`, не JSON.

| Поле | Значение |
|---|---|
| `csrf_token` | CSRF-токен |
| `id` | Только при редактировании, целое число |
| `type` | `useful` или `replacement` |
| `name` | Название, до 100 символов |
| `trigger` | Текст после «После…», до 160 символов |
| `action` | Действие, до 160 символов |
| `period` | `morning`, `day`, `evening` |
| `goal` | Обычный шаг, до 120 символов |
| `minimum` | Минимум, до 120 символов |
| `days` | Повторяемое поле: `0`–`6`, понедельник–воскресенье |
| `is_focus` | `on`, если выбран; иначе поля нет |
| `replacement_plan` | До 400 символов, обязательно для `replacement` |

Пример получения дней:

```python
days = [int(value) for value in request.form.getlist('days')]
is_focus = request.form.get('is_focus') == 'on'
```

Обязательно проверяйте данные повторно на сервере. Клиентская валидация улучшает UX, но обходится прямым запросом.

### `POST /habits/<id>/log`

`status`: `done`, `minimum` или `reset`. В демонстрационной модели отсутствие записи означает pending. `skipped` появляется через сценарий поддержки.

- `done` и `minimum` оба увеличивают дневной счётчик.
- Повторное нажатие для того же `habit.id` не должно добавлять второе выполнение.
- `reset` отменяет отметку; его семантику в истории/БД нужно согласовать.
- Для мягкого фокуса кнопка отправляет `minimum`, не `done`.
- Во время демо-паузы отметки блокируются и на фронтенде, и в обработчике.

Нужны проверка владельца привычки, допустимого дня и транзакционная запись. Нельзя доверять `<id>` из URL как доказательству права доступа.

### Поддержка

Обе формы отправляют `reason` и `csrf_token`:

| Значение | Подпись |
|---|---|
| `time` | Не хватило времени |
| `forgot` | Забыл(а) |
| `energy` | Не было сил |
| `plans` | Изменились планы |
| `hard` | Слишком сложно |
| `other` | Другая причина |

Сейчас нажатие на тег только выбирает radio. Причина передаётся при выборе мягкого шага или пропуска. Это намеренно: без явного отправления формы сервер не получает изменения.

`/support/step` **меняет план**, а не пишет выполненный лог. В рабочем приложении стоит передавать также конкретный `habit_id`: в демо поддержка относится к текущему фокусу.

### `POST /schedule/save`

- `intent`: `save`, `pause` или `resume`.
- `duration`: `today` или `dates`.
- `start`, `end`: ISO-даты `YYYY-MM-DD`, только для `dates`.
- `days`: повторяемые значения 0–6.
- `reminders`: `on` или отсутствие поля.
- `csrf_token`.

`end` — дата возобновления, **строго позже** начала. В демо `resume` не требует валидации остальных полей и не сохраняет незавершённые изменения расписания.

Рабочий алгоритм должен учитывать часовой пояс, пересечение общей и индивидуальной сетки дней и автоматическое окончание паузы. Эти правила пока не реализованы.

## 3. Контекст шаблонов

Общий контекст из `context_processor`:

```python
{
    'user': {'name': 'Евгений'},
    'active': 'today',       # каждый маршрут передаёт свой раздел
    'habit_count': 4,
    'days': [...],           # value, letter, short, name
    'periods': [...],        # id, label, icon, time
    'csrf_token': '...',     # в демо строка, не функция
    'demo_date': '2026-11-09'
}
```

В рабочем приложении пользователь берётся из авторизации. Если используете Flask-WTF с `csrf_token()`, измените только макрос `csrf_field()` в `partials/macros.html` и настройки CSRF на сервере; не убирайте защиту.

### Привычка

```python
habit = {
    'id': 1,
    'name': 'Читать каждый день',
    'type': 'useful',
    'task': 'Прочитать 10 страниц',
    'trigger': 'обеда',
    'action': 'прочитаю 10 страниц',
    'period': 'day',
    'goal': '10 страниц',
    'minimum': '1 страница',
    'minimum_task': 'Прочитать 1 страницу',
    'duration': '10 минут',
    'days': [0, 1, 2, 3, 4],
    'is_focus': True,
    'icon': 'book-open',
    'color': 'sage',
    'streak': 4,
    'clean_days': 0,
    'replacement_plan': ''
}
```

`icon` выбирайте из спрайта, `color` — из заранее разрешённых классов (`sage`, `blue`, `sand`, `rose`). Не отдавайте произвольные HTML/CSS пользователя в шаблон.

| Шаблон | Дополнительные данные |
|---|---|
| `today.html` | `date_label`, `focus`, `groups`, `logs`, `completed`, `total`, `stats`, `soft_habit_id`, `paused` |
| `habits.html` | `habits`, `selected`, `counts` |
| `habit_form.html` | `form`, `errors`, `templates`, `limit_warning` |
| `support.html` | `reasons`, `selected_reason`, `focus` |
| `statistics.html` | `stats`, `heatmap` |
| `schedule.html` | `schedule`, `errors` |
| `auth.html` | `tab`, `error` |

`groups` — список периодов с вложенным `tasks`. Фокус исключён из вложенных задач, чтобы не дублироваться. `logs` в демо — словарь с **целочисленными** ключами `habit.id`.

`stats`: `streak`, `longest`, `completed`, `planned`, `minimums`.

`heatmap`: список недель, каждая содержит 7 словарей `{'day': 1, 'level': 2}`. `day=0` — пустая ячейка; `level` только 0–4. Классы `.heat-level-0`…`.heat-level-4` уже поддерживают обе темы. При смене месяца также замените заголовок и подписи дат в `statistics.html` и обработчике календаря в `main.js`: сейчас «ноября» — часть фиксированного сценария.

## 5. Что не нужно переносить в бэкенд

В браузере остаются:

- `html[data-theme]` и `html[data-font]`;
- `localStorage['healthycats.theme']` / `['healthycats.font']`;
- переключение дней через checkbox и CSS;
- активный radio причины и подпись выбора;
- доступное мобильное меню и диалог шаблонов;
- базовая валидация для удобства пользователя.

Данные аккаунта, пароли, журналы выполнения и ключи LLM в localStorage не хранить.

## 6. Порядок подключения для команды

1. Зафиксировать формы и структуру данных из этого документа.
2. Подключить реальную авторизацию и источники пользовательских данных.
3. Заменить демо-список привычек и сохранение на БД.
4. Подключить логи, планировщик, серии и статистику; проверить единые идентификаторы и отсутствие двойного счёта.
5. Подключить расписание и паузу; затем поддержку и ИИ.
6. Заменить демонстрационные подсказки и проверить сценарии заново.
7. Удалить `demo_data.py`, `reset_demo`, технические лимиты демо и `PREVIEW_MODE` из боевой конфигурации либо отделить демонстрационную сборку.

## 7. Особенность встроенного демо-превью

Только при `PREVIEW_MODE=1` маршруты могут содержать `_demo`, а формы — скрытый `demo_token`. Это подписанный случайный идентификатор временной сессии, нужный, когда iframe/прокси не сохраняет cookies. Он не содержит пользовательских данных, но ссылка даёт доступ к той же демо-сессии, поэтому не используйте её для личной информации.

CSRF остаётся обязательным; тесты `tests/test_preview.py` проверяют работу без cookies и отклонение поддельных токенов. HTML отдаётся с `Cache-Control: no-store`, чтобы не переиспользовать устаревшие формы. Этот механизм — только для демонстрации, не замена настоящей авторизации. При интеграции оставьте `PREVIEW_MODE` выключенным и замените временное хранилище настоящей серверной сессией/БД.


## 8. Анимации и обновление отметок без перезагрузки

`motion.js` отвечает только за представление, `today.js` — за progressive enhancement формы. **Не нужен новый JSON endpoint**: сохраняется контракт `POST /habits/<id>/log → 303 → GET /today` с HTML-ответом. Обычная форма отправляет `application/x-www-form-urlencoded`, а `fetch` с `FormData` — `multipart/form-data`; Flask читает оба формата через `request.form`.

Заголовки `Accept: text/html` и `X-Requested-With: XMLHttpRequest` не дают никаких прав и не отключают CSRF. Токены исходной формы отправляются как прежде. На клиенте нет записи в БД или фиктивного засчитывания до ответа.

При изменении шаблонов сохраните UI-контракт:

| Хук | Значение |
|---|---|
| `.daily-plan[data-plan-paused]` | `true` / `false` для текущей паузы |
| `[data-task-id][data-task-status]` | Стабильный числовой ID и `pending`, `done`, `minimum`, `skipped`; в том числе у карточки фокуса |
| `form[data-habit-log]` | Исходная POST-форма с CSRF; кнопка `name="status"` |
| `.plan-counter` | Текст счётчика и `aria-live`; без генерируемых на клиенте чисел |
| `.progress-track > span` | Ширина в процентах; у track актуальные `aria-valuenow` / `aria-valuemax` |
| `#toast-stack .toast` | Уже экранированные серверные сообщения |

Если план изменён в другой вкладке, новые строки и структура берутся из ответа. При ошибке UI предлагает обновиться, не повторяя POST автоматически. Тайм-аут не доказывает отсутствия записи на сервере. На реальном бэкенде нужны идемпотентность, проверка владельца, транзакции и полноценная обработка истёкшей авторизации; текущий UI при неожиданной странице предлагает перезагрузку.

Сохраните порядок загрузки из `head.html`: основной CSS, слой движения; deferred `motion.js`, `main.js`, `today.js`. Если требуется JSON API вместо HTML, меняйте адаптер `today.js`, а не функции анимации. Подробности — [MOTION.md](MOTION.md).
