# Рабочий backend practical-work-06

## Состав

Рабочая сборка запускается через app.py и использует SQLite. Существующий демонстрационный стенд сохранён отдельно внутри app.py: старые контрактные тесты вызывают его с TESTING=True, а рабочие интеграционные тесты явно устанавливают USE_DEMO=False.

- auth.py — регистрация, вход и проверка хеша пароля (Werkzeug).
- database.py — существующий слой SQLite проекта: аккаунты, привычки, отметки, расписание и паузы.
- habits_manager.py — серверная валидация форм, каталог шаблонов, фильтрация и рекомендация по нагрузке.
- daily_planner.py — сборка сегодняшних задач из данных пользователя.
- streak_calculator.py — недельные показатели и серии по фактическим отметкам.
- statistics_heatmap.py — календарная матрица реальной истории.
- miss_support.py — каталог советов, причин и сохранение причины пропуска.
- schedule_adapter.py — рекомендация по дню с повторяющимися пропусками.
- ai_client.py — честный локальный fallback из JSON-каталога. Внешний AI-провайдер пока не подключён.

## Контракт

Реализованы маршруты из INTEGRATION.md: /, /today, /habits, /habits/new, /habits/<id>/edit, POST /habits/save, POST /habits/<id>/log, /support, POST /support/step, POST /support/skip, /statistics, /schedule, POST /schedule/save, /settings, /auth, POST /login, POST /register, /logout, /health.

Все формы, изменяющие состояние, используют CSRF-токен из подписанной Flask-сессии. Пользовательские маршруты требуют входа. Привычки выбираются по user_id, а не только по переданному URL идентификатору. Отметки уникальны по habit_id + log_date; повторный запрос обновляет ту же запись, а reset удаляет отметку. Пароль никогда не сохраняется в открытом виде.

## Статусы и календарь

- done и minimum — выполненный прогресс.
- skipped — пропуск с необязательной причиной.
- reset — команда удаления дневной отметки, а не сохраняемый статус.
- День окончания паузы трактуется как первый день возобновления (интервал паузы полуоткрытый: start_date <= day < end_date).
- Общие рабочие дни пересекаются с индивидуальными днями привычки.
- Статистика строится по логам SQLite, а календарная тепловая карта считает done и minimum.

Серия на текущем этапе означает календарные дни, в которые отмечен хотя бы один done или minimum; дни без запланированных привычек и активная пауза её не прерывают. Пропуск или незавершённый запланированный день прерывает серию. Это явное промежуточное правило: его необходимо подтвердить с командой, прежде чем считать алгоритм окончательной бизнес-логикой.

## Запуск локально

Из каталога practical-works/practical-work-06/src:

    python -m venv .venv
    # Windows:
    .venv\Scripts\activate
    # macOS/Linux:
    source .venv/bin/activate
    pip install -r requirements-dev.txt
    python app.py

Переменные окружения:
- SECRET_KEY — задать постоянное случайное значение вне локального теста.
- HEALTHYCATS_DATABASE — путь к SQLite-файлу; по умолчанию src/berezhno.db.
- HEALTHYCATS_TIMEZONE — часовой пояс дат приложения; по умолчанию Europe/Moscow.
- COOKIE_SECURE=1 — включить Secure-cookie при работе по HTTPS.

## Проверки

    python -m pytest -q
    python -m compileall -q .

Существующие 55 тестов проверяют демонстрационный UI-контракт. tests/test_backend.py проверяет рабочую сборку: регистрацию, хеширование пароля, CSRF, вход/выход, владение данными, повторные отметки, минимум, паузу, пропуск и рендер страниц.

## Известные ограничения

1. Уведомления не отправляются: сохраняется только пользовательская настройка.
2. Внешний LLM/API не настроен: экран поддержки использует локальный проверенный fallback и не отправляет личные сведения.
3. Автоматический план от ИИ не генерируется до появления ключа и утверждённого провайдера.
4. Ограничение количества привычек оставлено предупреждением, а не жёстким лимитом: решение о лимите в материалах анализа не согласовано.
5. Правило серии описано выше и требует подтверждения команды.
6. Настройки темы и размера шрифта остаются в браузере (localStorage), как и указано в интеграционной инструкции.
