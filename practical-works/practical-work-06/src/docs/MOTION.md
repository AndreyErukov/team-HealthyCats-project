# Ненавязчивые анимации «бережно»

Анимации добавлены поверх существующего интерфейса, без изменения палитры, логотипа, структуры экранов и демонстрационной бизнес-логики. Нет звука, конфетти, бесконечного декоративного движения и новых runtime-зависимостей.

## Что анимируется

| Элемент | Поведение | Длительность |
|---|---|---|
| Шкала дня и недельная шкала | При загрузке плавно заполняются до серверного значения | 680 мс |
| Шкала дня после отметки | Переходит от текущего видимого заполнения к новому; при отмене уменьшается | 680 мс |
| «Сделано», «Минимум», фокус дня | Мягкая подсветка строки, лёгкое увеличение отметки, прорисовка галочки | 280–680 мс |
| Счётчик | Лёгкое появление нового текста; значение сразу соответствует серверу | 300 мс |
| Кнопки | Мягкий hover на устройствах с мышью, сжатие при нажатии, световая волна от точки касания | 140–450 мс |
| Карточки | Небольшой сдвиг и появление при первом попадании в область просмотра | 370 мс + задержка до 140 мс |
| Фильтр привычек | Появление подходящих карточек и изменение высоты списка | 340–370 мс |
| ИИ-заглушки | Плавное раскрытие/сворачивание существующего подготовленного текста | 300 / 180 мс |
| Диалог шаблонов | Появление и закрытие; Esc и нативное управление фокусом сохранены | 260 / 140 мс |
| Checkbox, radio, календарь | Короткий отклик выбранного элемента | 230–240 мс |
| Уведомления | Появление, мягкое закрытие, приостановка таймера при наведении/фокусе | 200 / 160 мс |

Во время запроса на кнопке есть небольшой индикатор сохранения. Он существует только до ответа или тайм-аута **12 секунд**, а не работает постоянно.

## Файлы

- `static/css/motion.css` — отдельный слой переходов, hover/press, волна нажатия, состояние загрузки и отключение движения.
- `static/js/motion.js` — небольшие функции Web Animations API, без библиотек. Экспорт `window.BerezhnoMotion`: `progress`, `markTask`, `resize`, `reveal`, `disclose`, `openDialog`, `closeDialog`, `counter`, `animate`, `enabled`.
- `static/js/main.js` — существующая UI-логика; вызывает функции движения для фильтров, диалога, раскрытий и вкладок. Экспорт `window.BerezhnoUI` нужен для доступных уведомлений при обновлении плана.
- `static/js/today.js` — улучшение обычных POST-форм отметок через `fetch`, без полной перезагрузки страницы.
- `templates/partials/head.html` — порядок: `style.css` → `motion.css`; deferred `motion.js` → `main.js` → `today.js`.

CSS не скрывает карточки до выполнения JavaScript. Если анимационный API отсутствует, состояние меняется сразу; основной интерфейс остаётся доступен.

## Отметка — не просто визуальный эффект

1. Пользователь нажимает «Отметить», «Сделано», «Минимум» или отмену.
2. `today.js` собирает исходную форму, включая `csrf_token`, при необходимости `demo_token` и значение нажатой кнопки `status`.
3. Отправляется тот же `POST /habits/<id>/log`; **нового API нет**. Сервер отвечает `303`, затем браузер получает HTML страницы `/today`.
4. Только после успешного ответа обновляются строка задачи, счётчик, доступные кнопки, пауза и шкала. Анимация показывает уже подтверждённое демонстрационное состояние.

Нет оптимистичного засчитывания до ответа. На время запроса кнопки плана заблокированы: быстрые повторные действия не создают параллельных записей. Если структура плана изменилась, используется свежий серверный план. Новые защитные поля и подписанный URL демо сохраняются.

При сетевой ошибке, HTTP-ошибке, неожиданном ответе или тайм-ауте кнопки вновь доступны и появляется понятное сообщение с действием **«Обновить»**. Повторный POST автоматически не отправляется. После потери ответа нельзя утверждать, что сервер ничего не записал: поэтому текст предлагает обновить страницу и проверить результат.

**Без JavaScript** остаются обычные работающие POST-формы и редиректы. То же резервное поведение используется, если необходимых браузерных API/UI-модуля нет или документ находится в sandbox с непрозрачным origin, где same-origin fetch недоступен. Это не превращает Jinja-шаблоны в автономный HTML-файл: для них по-прежнему нужен Flask.

## Доступность и прерывание эффектов

- `prefers-reduced-motion: reduce` отключает CSS-анимации, переходы и плавную прокрутку; модуль JS не запускает Web Animations. Настройка отслеживается и на уже открытой странице: активные эффекты завершаются в правильном конечном состоянии.
- У счётчика есть `aria-live`, у шкалы — актуальные `aria-valuenow` / `aria-valuemax`, у плана во время запроса — `aria-busy`.
- После замены нажатой кнопки фокус возвращается к соответствующему действию. Если человек уже перешёл за пределы плана, фокус не перехватывается.
- На экране с живыми отметками отключено автоматическое scroll anchoring: браузер не сдвигает страницу вслед за нижним блоком советов при изменении высоты задачи. Стандартная прокрутка и управление клавиатурой остаются доступны.
- При быстрых сменах фильтра или раскрытия предыдущая анимация отменяется; временные `overflow` / `inert` и декоративные элементы очищаются.
- Выбор шаблона сначала завершает закрытие modal, затем подставляет значения и фокусирует поле, уже доступное для ввода.

## Проверка

```bash
python tests/motion_browser.py
```

Нужны запущенный стенд и Chromium из `requirements-dev.txt`. Полный сценарий транспорта без cookies выполняется при `PREVIEW_MODE=1`; в обычном локальном режиме этот отдельный сценарий помечается `SKIP`. Это проверка HTTP-транспорта без cookies, **не** утверждение о проверке всех iframe-политик реальных браузеров.

Тест проверяет реальные промежуточные кадры заполнения через Web Animations API, подтверждение сервером, быстрые повторы, ошибки/тайм-аут/CSRF, фокус, мобильную прокрутку, reduced motion, диалоги, раскрытия и нативные формы. Общие проверки и ограничения описаны в [TESTING.md](TESTING.md).
